## 2. Detalles Técnicos y Contratos (SSOT)

Este documento es la **Fuente Única de Verdad** para el Hito 1.9.7. Cualquier plan de implementación se define a continuación.

### Estrategia de Reemplazo Dinámico
Para mantener la fluidez de la conversación ("en la misma burbuja"):
1.  **Identificación:** El mensaje de bienvenida inicial debe tener un ID único o ser identificable (ej. el último mensaje del bot presente al cargar).
2.  **Actualización:** Al recibir la respuesta del primer `INIT` (Handshake), el script debe buscar este elemento.
3.  **Inyección:**
    *   **Si existe:** Reemplazar su `innerHTML` con la nueva respuesta (manteniendo timestamp actualizado).
    *   **Si no existe:** Crear una nueva burbuja (comportamiento standard).

### Estrategia de Acceso VPN (Google OAuth)
Google no permite direcciones IP como orígenes autorizados.
*   **Solución:** Utilizar el servicio DNS wildcard `nip.io`.
*   **Configuración en Google Cloud:** Agregar `http://172.26.0.1.nip.io` (y con puertos: `http://172.26.0.1.nip.io:7700`).
*   **Acceso Usuario:** El usuario debe ingresar al navegador usando `http://172.26.0.1.nip.io:7700` en lugar de la IP directa.

### Requerimientos de Renderizado JSON
El frontend (`chatbot.js`) debe interceptar la respuesta del webhook y aplicar la siguiente lógica:

1.  **Parseo:** Intentar `JSON.parse(respuesta)`.
2.  **Si es JSON válido:**
    *   Extraer `response` -> Mostrar como mensaje del bot.
    *   Extraer `suggestions` -> Generar botones clickeables debajo del mensaje.
3.  **Si falla el parseo (Fallback):**
    *   Mostrar el texto crudo tal cual llega.
